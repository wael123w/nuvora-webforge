# Nuvora WebForge Interface Tour

This annotated tour explains the visible areas of the desktop application. The screenshots are captured from the product interface and are accompanied by a practical control map.

## 1. Build and preview workspace

![Main workspace](assets/03-annotated-workspace.png)

| Area | Purpose |
|---|---|
| **Website brief** | Enter the project purpose, pages, sections, language, style direction, and responsive requirements. |
| **Project technology** | Choose static HTML/CSS/JavaScript or React + Vite before generation. |
| **Visual reference** | Optionally attach a PNG, JPG, or WEBP image to communicate visual direction to the selected provider. |
| **Preview / Code / Files** | Switch between responsive project review, code editing, and the project file map. |
| **Refine with AI** | Submit one focused change request after generation. The application validates the replacement project before updating local files. |

## 2. Generated project file map

![Files workspace](assets/04-annotated-files.png)

| Area | Purpose |
|---|---|
| **Project identity** | Shows the generated project name and selected framework. |
| **Run instructions** | Shows the provider-generated instructions for opening or running the project. |
| **File list** | Shows root files and organised folders with file sizes. |
| **Edit action** | Opens an individual file in the integrated Monaco editor. |

## 3. React + Vite workflow

![React workspace](assets/05-annotated-react.png)

| Area | Purpose |
|---|---|
| **React + Vite selection** | Confirms that the generated project uses the React + Vite structure. |
| **Project state** | Indicates that the project has been generated and records its file count in the status bar. |
| **Run guidance** | Explains that the copied React project is run through `pnpm install` and `pnpm dev` in its own project folder. |

> Screenshots show the product workflow only. Buyer-owned API keys and provider credentials are never displayed in the documentation.
